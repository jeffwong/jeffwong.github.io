Experimentation has many special designs, each warranting a specialized type of model. Managing all of these can be difficult. Keeping the implementation sane is harder. In this post, we show that four features of experimental design, in any combination, are covered by one model, which we can fit efficiently. Let’s start with the motivation.

A streaming service wants to know whether a new playback setting helps. Accounts are shared by a household, and each account has up to five profiles. The setting changes how the app behaves on the household’s devices, so the service randomizes at the account level: it shows the account a prompt that invites its profiles to turn the setting on. Each profile then decides for itself. The service is cautious, so it ramps the prompt over four days, from 5% of new accounts to 50%. It measures each profile’s hours watched and its rebuffers per play.

This is a cluster randomized, encouragement experiment, with propensities that change by cohort, and with a ratio metric. In previous posts we analyzed several of these features separately: ratio metrics with a bivariate regression and the delta method, local average treatment effects with an instrument, and CUPED from aggregated data. This post claims that one model covers every combination of these features, and that the model can be fit exactly from a compressed dataset whose size does not grow with the number of rows.

The data in this post is synthetic and the scenario is educational. It does not describe a production system.

The Running Example

Each account \(a\) enters the experiment on \(\text{day}_a \in \{1, 2, 3, 4\}\), and the accounts that enter on the same day form a cohort. An account is prompted, \(Z_a = 1\), with probability \(e_{\text{day}}\), which ramps up from day to day. Each profile \(p\) of the account has covariates measured before the experiment: hours per day \(x_1\), tenure in years \(x_2\), whether it is a kids profile, and its main device. A prompted profile turns the setting on, \(T_{ap} = 1\), more often if it watches a lot, and less often if it is a kids profile. Take-up also depends on an engagement level that we do not observe, which also raises the profile’s hours. Profiles of the same account share network quality, so their outcomes are correlated.

Code 
simulate_accounts <- function(n_accounts = 20000, propensity = c(0.05, 0.10, 0.25, 0.50), force_Z = NULL,
                              full_compliance = FALSE, one_profile = FALSE) {
  accounts <- tibble(
    account = seq_len(n_accounts),
    day = sample.int(length(propensity), n_accounts, replace = TRUE, prob = rev(seq_along(propensity))),
    n_profiles = if (one_profile) 1L else pmin(1L + rpois(n_accounts, 1.2), 5L),
    quality = rnorm(n_accounts, 0, 0.5),                       # shared by the account's profiles
    engagement = rnorm(n_accounts, 0, 0.5)                     # account part of engagement
  ) |>
    mutate(Z = rbinom(n(), 1, propensity[day]), Z = if (is.null(force_Z)) Z else force_Z)
  accounts[rep(accounts$account, accounts$n_profiles), ] |>
    mutate(
      profile = sequence(accounts$n_profiles),
      kids = rbinom(n(), 1, if_else(profile == 1, 0.05, 0.3)),   # the first profile is rarely a kids profile
      device = sample(c("tv", "mobile", "web"), n(), replace = TRUE, prob = c(0.5, 0.35, 0.15)),
      engagement_p = engagement + rnorm(n(), 0, 0.8),          # the profile's engagement, not observed
      x1 = rlnorm(n(), 0.7 - 0.12 * day - 0.6 * kids + 0.3 * engagement_p, 0.6),
      x2 = rgamma(n(), 2, 1) * (1.2 - 0.15 * day),
      complier = rbinom(n(), 1, plogis(-0.3 + 0.5 * log(x1) + 0.6 * engagement_p - 0.8 * kids)),
      T = if (full_compliance) Z else Z * complier,
      y = 0.5 + 0.8 * x1 + 0.1 * x2 + 0.5 * engagement_p + quality +                 # hours per day
        T * (0.3 + 0.15 * x1 - 0.2 * kids) + rnorm(n(), 0, 0.5 + 0.3 * x1),
      D = 1 + rpois(n(), exp(1 + 0.4 * log(x1) + 0.3 * engagement_p + 0.2 * (device == "tv")) * (1 + 0.15 * T)),      # plays
      N = rpois(n(), D * 0.08 * exp(-0.4 * T * (1 + 0.5 * (device == "mobile")) + 0.4 * quality - 0.2 * engagement_p))  # rebuffers
    )
}

Why not add up each account’s profiles first, and analyze one row per account? Because the treatment, the covariates and the question all live at the profile level. Within a prompted account, some profiles turned the setting on and some did not, so an account total mixes treated and untreated profiles. A kids profile and an adult profile watch differently and respond differently, and an account total mixes those too. And the business question is about profiles: how much does the setting change a profile’s hours, and its rebuffers per play, when the profile actually uses it? So we model each profile as a row, \(y_{ap}\), and handle the correlation between profiles of the same account in the standard errors.

Because we wrote the simulation, we can compute the true effects. We simulate the same accounts twice, once with every account prompted and once with none, and look at the profiles that turn the setting on when prompted, the compliers. Our two targets are the effect of the setting on compliers’ hours, \(\tau_{LATE}\), and on compliers’ rebuffers per play,

\[\tau_R = \frac{E[N(1) \mid C]}{E[D(1) \mid C]} - \frac{E[N(0) \mid C]}{E[D(0) \mid C]},\]

where \(N(t)\) and \(D(t)\) are a profile’s rebuffers and plays with the setting on, \(t = 1\), or off, \(t = 0\), and \(C\) denotes the compliers.

truth_pair <- function(seed, n_accounts = 1e6) {

}

One Universal Model

The design

The experiment has four features, and each one changes the analysis. Keeping track of the complexity is hard, but we will collapse these into a single, universal model.

  1. Clusters. We randomize accounts, and profiles of the same account are correlated, so the standard errors must be cluster robust.
  2. Encouragement. We randomize the prompt \(Z_a\), but the treatment received \(T_{ap}\) is chosen by the profile, so \(Z\) is an instrument for \(T\).
  3. A ramp. The probability of a prompt depends on the cohort, so each account gets the inverse propensity weight \(w_a = 1/\hat e_{\text{day}}\) if prompted and \(w_a = 1/(1 - \hat e_{\text{day}})\) if not, where \(\hat e_{\text{day}}\) is the share of the accounts entering on that day that were prompted.
  4. A ratio metric. Rebuffers per play needs a numerator and a denominator, modeled jointly.

We rely on three assumptions.

(A1) Accounts are independent of each other. Profiles of the same account may be correlated in any way.

(A2) Within a cohort, the prompt is randomized with probability \(e_{\text{day}}\), independently of everything else.

(A3) The prompt affects a profile’s outcomes only through \(T\) (exclusion), and no profile turns the setting on only when it is not prompted (monotonicity). Monotonicity holds trivially here, because an unprompted profile cannot turn the setting on.

The model

Two stage least squares with weights and cluster robust standard errors handles all four features at once. It is the universal model, and is formulated as

\[\begin{align} y_{ap} &= \underbrace{\beta_{00} + (x_{ap} - x_{ref})^\top \beta_{0x}}_{\text{baseline line}} + T_{ap} \underbrace{\left(\beta_{10} + (x_{ap} - x_{ref})^\top \beta_{1x}\right)}_{\text{treatment line}} + \varepsilon_{ap} && \text{second stage} \\ T_{ap} &= \gamma_{00} + (x_{ap} - x_{ref})^\top \gamma_{0x} + Z_a \left(\gamma_{10} + (x_{ap} - x_{ref})^\top \gamma_{1x}\right) + \nu_{ap} && \text{first stage for } T \\ T_{ap} (x_{apj} - x_{ref,j}) &= \gamma^{(j)}_{00} + (x_{ap} - x_{ref})^\top \gamma^{(j)}_{0x} + Z_a \left(\gamma^{(j)}_{10} + (x_{ap} - x_{ref})^\top \gamma^{(j)}_{1x}\right) + \nu^{(j)}_{ap} && \text{first stage for interaction } j = 1, \dots, k \end{align}\]

Here \(x_{ap}\) is the vector of the profile’s \(k = 5\) covariates: hours per day, tenure, the kids indicator, and the device as two indicators, mobile and web, so that tv is the baseline. \(x_{apj}\) is its \(j\)-th entry, and \(x_{ref}\) is a fixed reference point (see Centering the covariates).

The second stage describes a profile’s outcome with two lines in its covariates. The baseline line is the outcome without the setting, and the treatment line is the effect of the setting. \(\beta_{10}\) is the main effect of the treatment, the effect at \(x = x_{ref}\), and \(\beta_{1x}\) lets the effect change with each covariate. Every covariate interacts with the treatment, but the covariates do not interact with each other.

The first stage handles the encouragement. Profiles choose whether to turn the setting on, so profiles with \(T = 1\) differ from profiles with \(T = 0\) in ways other than the setting. The treatment \(T\) and its \(k\) interactions \(T (x_j - x_{ref,j})\) are therefore endogenous, and each gets its own first stage equation. Each equation has the same form as the second stage, with the randomized prompt \(Z_a\) in place of \(T\): it predicts the endogenous regressor from the covariates, the prompt, and the prompt’s interactions with the covariates. The second stage is then fit with these predictions in place of \(T\) and its interactions.

Three more choices complete the model. Each account carries its inverse propensity weight \(w_a\), which handles the ramp. The standard errors add up the profiles of an account before squaring, which makes them cluster robust. And one fit can hold several outcome columns: hours \(y\), and for the ratio metric, rebuffers \(N\), plays \(D\), and two more columns, \(TN\) and \(TD\) (see What the model estimates).

What the model estimates

When applying our universal model to this cluster randomized encouragement experiment, the model will be estimating the Local Average Treatment Effect (LATE). However, when modeling other experiments, this universal model can also model an average treatment effect, and an intent to treat effect.

The treatment line describes the compliers. The prompt changes the treatment only for compliers, the profiles that turn the setting on when prompted. Every other profile has the same \(T\) with or without the prompt, so the first stage, and the treatment line it feeds, can only learn from compliers. The treatment line is a fit to the compliers’ average effect at each value of the covariates, \(\tau_C(x)\), where each \(x\) counts in proportion to how many compliers have it. The appendix derives this from the model’s equations.

The LATE is the treatment line at the compliers’ average covariates. Because the line is fit to the compliers, its average over the compliers is their average effect, the LATE. A line’s average is its value at the average input, so

\[\boxed{\tau_{LATE} = \beta_{10} + (\bar x_C - x_{ref})^\top \beta_{1x}}\]

where \(\bar x_C\) is the mean of the covariates among compliers. This holds even when \(\tau_C(x)\) is not a line. We never observe who is a complier, but we can estimate their mean covariates with a ratio of two intent to treat effects. The product \(T \cdot x\) is nonzero only for profiles that took the treatment, so under (A3)

\[\bar x_C = \frac{E[T \cdot x \mid Z = 1] - E[T \cdot x \mid Z = 0]}{E[T \mid Z = 1] - E[T \mid Z = 0]}.\]

In our experiment the compliers watch more than the average profile, so reading the line at the average profile would answer a different question than the LATE.

The ratio needs the compliers’ own levels. Write \(\ell_N\) for the treatment line of the outcome \(N\) read at \(\bar x_C\), and similarly for other outcomes. \(\ell_N\) is the compliers’ effect on rebuffers, but \(\tau_R\) needs the compliers’ levels, \(E[N(1) \mid C]\) and \(E[N(0) \mid C]\). The baseline line does not give them: it describes all profiles, and compliers differ from the rest in ways that \(x\) does not capture. The column \(TN\) does. It equals \(N\) for profiles that turned the setting on and 0 otherwise, so its treatment line is fit to the compliers’ rebuffers with the setting on, and \(\ell_{TN} = E[N(1) \mid C]\). Subtracting the effect gives \(E[N(0) \mid C] = \ell_{TN} - \ell_N\). The same holds for plays, so

\[\tau_R = \frac{\ell_{TN}}{\ell_{TD}} - \frac{\ell_{TN} - \ell_N}{\ell_{TD} - \ell_D}.\]

These are the two effects of our running example. The same fitted model answers other questions too.

  1. The effect for a type of profile. Reading the treatment line at other covariates gives the effect for profiles like those, for example kids profiles that watch one hour a day.
  2. How the effect varies. The slopes \(\beta_{1x}\) are the heterogeneity in the effect, for example how much smaller it is for kids profiles.
  3. Simpler designs. Each feature of our experiment can be switched off, and switching it off gives the textbook analysis of a simpler design:
    • No encouragement: when every prompted profile takes the treatment, \(T = Z\), the first stage predicts \(T\) perfectly, and the model is weighted least squares.
    • No clusters: when each account has one profile, the cluster robust standard errors are the heteroskedasticity robust standard errors.
    • No ramp: when the propensity is the same every day, the weights are a constant and cancel.
    • No ratio: when every row has \(D = 1\), the ratio reduces to the LATE on \(N\).
    • No covariates: the model is a difference in means, or a Wald ratio with encouragement.

The switches touch different parts of the model, the first stage, the standard errors, the weights and the outcome columns, so they combine freely. A purely randomized AB test with one row per user and a mean metric is the model with every switch off; our experiment is the model with every switch on. The appendix proves each reduction, and Table 3 in Checking every design tests all 16 combinations against textbook code.

How the model is fit

In this section we describe how to train the model from scratch using first principles. It is possible to use off the shelf software like iv_robust from estimatr, but we write out all the steps and linear algebra here in order to be prepared for how to derive the compression formulas.

Centering the covariates

We center each covariate at a fixed reference point \(x_{ref}\). Centering works like demeaning the columns, except that \(x_{ref}\) is a constant we choose before the experiment rather than the sample mean. Any choice gives the same fitted model; it only changes which point the coefficients \(\beta_{00}\) and \(\beta_{10}\) describe. We use a constant because the compressed version of the model, later in the post, is built in one pass over the data, before the sample mean is known. Here \(x_{ref}\) is 2 hours per day, 2 years of tenure, an adult profile and a tv. From here on, \(x_{ap}\) denotes the centered covariates, \(x_{ap} - x_{ref}\), so the reference point is \(x = 0\). With an intercept in front, the profile rows of the prompted account from Table 1 become

x_cols <- c("x1", "x2", "kids", "mobile", "web")

prepare <- function(profiles, ramp = TRUE) {
  e_hat <- profiles |>
    distinct(account, day, Z) |>
    group_by(day) |>
    summarise(e_hat = mean(Z))
  profiles |>
    left_join(e_hat, by = "day") |>
    mutate(w = if (ramp) if_else(Z == 1, 1 / e_hat, 1 / (1 - e_hat)) else 1,     # inverse propensity weight
           mobile = as.numeric(device == "mobile"), web = as.numeric(device == "web"),
           TN = T * N, TD = T * D)
}

The two stages as matrices

With centered covariates, the second stage is \(y_{ap} = m_{2,ap}^\top \beta + \varepsilon_{ap}\), with regressors \(m_{2,ap} = (1, \; x_{ap}, \; T_{ap}, \; T_{ap} x_{ap})\) and coefficients \(\beta = (\beta_0, \beta_1)\), where \(\beta_0 = (\beta_{00}, \beta_{0x})\) is the baseline line and \(\beta_1 = (\beta_{10}, \beta_{1x})\) is the treatment line. The first stage predicts the endogenous regressors \(T_{ap}\) and \(T_{ap} x_{ap}\) from the instruments \(m_{1,ap} = (1, \; x_{ap}, \; Z_a, \; Z_a x_{ap})\),

\[(T_{ap}, \; T_{ap} x_{ap}) = \Gamma^\top m_{1,ap} + \nu_{ap},\]

which stacks the \(k + 1\) first stage equations of the model, one for \(T_{ap}\) and one for each of the \(k\) entries of \(T_{ap} x_{ap}\). \(\Gamma\) has one column of first stage coefficients per equation, the \(\gamma\) and the \(\gamma^{(j)}\), and \(\nu_{ap}\) stacks the first stage errors. Stacking the rows gives the matrices \(M_1\) and \(M_2\). Here are their rows for the prompted account. They differ only in their second half, where \(M_1\) multiplies by the prompt \(Z\) and \(M_2\) by the treatment received \(T\).

With the weights in \(W = \text{diag}(w)\), two stage least squares replaces \(M_2\) with its first stage prediction \(\hat M_2 = M_1 (M_1^\top W M_1)^{-1} M_1^\top W M_2\) and regresses \(y\) on it with weights \(W\). \(M_1\) and \(M_2\) have the same number of columns, one instrument for each regressor, so the estimate simplifies to

\[\boxed{\hat\beta = (M_1^\top W M_2)^{-1} M_1^\top W y.}\]

The matrix \(M_1^\top W M_2\) is the weighted cross product of the instruments with the regressors, and it plays the role that \(X^\top X\) plays in least squares.

The residuals use the treatment actually received, \(\hat\varepsilon_{ap} = y_{ap} - m_{2,ap}^\top \hat\beta\). The cluster robust covariance of \(\hat\beta\) is the sandwich

\[\boxed{\widehat{\text{Cov}}(\hat\beta) = (M_1^\top W M_2)^{-1} \left[\sum_a \left(\sum_p w_a \, m_{1,ap} \, \hat\varepsilon_{ap}\right) \left(\sum_p w_a \, m_{1,ap} \, \hat\varepsilon_{ap}\right)^\top \right] (M_1^\top W M_2)^{-\top}.}\]

The inner sum adds up the residuals of an account’s profiles, each multiplied by its instruments. Profiles are added within an account before the outer product is taken, so their correlation enters the covariance. That is what makes it robust to clustering.

The outcome can be a matrix \(Y\) with one column per metric. All columns share \(M_1\), \(M_2\) and \(M_1^\top W M_2\), so the coefficients form a matrix \(\hat B\) with \(2(k+1)\) rows and one column per metric. Stacking the inner sums of all the metrics into one vector per account gives the covariance between the coefficients of different metrics, which the ratio needs.

From coefficients to effects

Each effect is a function of \(\hat B\). Reading a treatment line at \(\bar x_C\) is a dot product with the delta vector \(\delta = (0, \dots, 0, \; 1, \; \bar x_C - x_{ref})\), which has zeros for the baseline line. Here \(\bar x_C\) is the compliers’ mean of the original covariates, so \(\bar x_C - x_{ref}\) is that mean in centered units. Then \(\ell_N = \delta^\top \hat\beta_N\) for the column \(\hat\beta_N\) of \(\hat B\) that belongs to \(N\), and the LATE is \(\delta^\top \hat\beta_y\). The variance of each effect follows from the delta method, with the gradient of the effect with respect to \(\hat B\) and the joint covariance of all the coefficients. We never pick coefficients by hand: we only write the effect as a function of \(\hat B\).

fit_rows fits the model on the profile rows. The outcome matrix holds hours \(y\) and the four columns for rebuffers per play.

Code 
y_cols <- c("y", "N", "D", "TN", "TD")
d <- length(x_cols) + 1                              # intercept and k covariates
o <- length(y_cols)                                  # number of outcome columns

fit_rows <- function(df) {
  m <- design(df); Y <- as.matrix(df[y_cols])
  M1_W_M2 <- crossprod(m$M_1 * df$w, m$M_2)                                   # M_1' W M_2
  B <- solve(M1_W_M2, crossprod(m$M_1 * df$w, Y))
  eps <- Y - m$M_2 %*% B                                                # second stage residuals
  inner <- do.call(cbind, map(seq_len(o), \(l) rowsum(m$M_1 * (df$w * eps[, l]), df$account)))   # one row per account
  M1_W_M2_inv <- kronecker(diag(o), solve(M1_W_M2))
  list(B = B, V = M1_W_M2_inv %*% crossprod(inner) %*% t(M1_W_M2_inv))
}

complier_mean <- function(df) {
  if (all(df$T == df$Z)) return(colSums(df$w * df[x_cols]) / sum(df$w))
  arm <- df |>
    group_by(Z) |>
    summarise(across(all_of(x_cols), \(v) sum(w * T * v) / sum(w)), T = sum(w * T) / sum(w))
  unlist(arm[arm$Z == 1, x_cols] - arm[arm$Z == 0, x_cols]) / (arm$T[arm$Z == 1] - arm$T[arm$Z == 0])
}

effect_functions <- function(x_C, x_ref, cols) {
  delta <- c(rep(0, length(x_ref) + 1), 1, x_C - x_ref)               # reads a treatment line at x_C
  line <- \(B, col) sum(delta * B[, col])
  effect_list <- list(tau_LATE = \(B) line(B, "y"))
  if ("TN" %in% cols) effect_list$tau_R <- \(B) line(B, "TN") / line(B, "TD") - (line(B, "TN") - line(B, "N")) / (line(B, "TD") - line(B, "D"))
  effect_list
}

effects <- function(fit, x_C, x_ref) {
  effect_list <- effect_functions(x_C, x_ref, colnames(fit$B))
  theta <- as.vector(fit$B)
  map_dfr(names(effect_list), \(nm) {
    f <- \(th) effect_list[[nm]](matrix(th, nrow(fit$B), dimnames = list(NULL, colnames(fit$B))))
    grad <- gradient(f, theta)
    tibble(effect = nm, estimate = Re(f(theta)), se = sqrt(drop(t(grad) %*% fit$V %*% grad)))
  })
}

Compressing the Universal Model

The model is universal, but fitting it on the profile rows is expensive when there are hundreds of millions of them and dozens of metrics. We now derive, from first principles, a compressed dataset that still gives the exact estimate and the exact covariance. We start with the math, then build the compressed dataset by hand for two simple cases, and then for the full model.

What the model needs

The estimate needs \(M_1^\top W M_2\) and \(M_1^\top W Y\), which are sums over profile rows. Within an account, the instruments are \(m_{1,ap} = (1, x_{ap}, Z_a, Z_a x_{ap})\), and \(Z_a\) and \(w_a\) are the same for every profile, so these sums only need three blocks per account:

\[S_a = \sum_p \begin{pmatrix} 1 \\ x_{ap} \end{pmatrix} \begin{pmatrix} 1 & x_{ap}^\top \end{pmatrix}, \qquad S^T_a = \sum_p T_{ap} \begin{pmatrix} 1 \\ x_{ap} \end{pmatrix} \begin{pmatrix} 1 & x_{ap}^\top \end{pmatrix}, \qquad S^Y_a = \sum_p \begin{pmatrix} 1 \\ x_{ap} \end{pmatrix} y_{ap}^\top.\]

\(S_a\) holds the account’s number of profiles, the sums of its covariates, and the sums of the products of every pair of covariates. \(S^T_a\) holds the same sums over the profiles that took the treatment. \(S^Y_a\) holds the sums of the outcomes, and of the outcomes times each covariate; here \(y_{ap}\) is the row of \(Y\), all outcome columns of the profile. Because \(Z_a\) and \(w_a\) are constant within an account, each block of \(M_1^\top W M_2\) is a weighted sum of these blocks over accounts. For example, the block that pairs the instruments \((Z_a, Z_a x_{ap})\) with the regressors \((T_{ap}, T_{ap} x_{ap})\) is \(\sum_a w_a Z_a S^T_a\).

The covariance needs the inner sums \(\sum_p w_a m_{1,ap} \hat\varepsilon_{ap}\). Split \(\hat B\) into its baseline and treatment blocks, \(\hat B_0\) and \(\hat B_1\). The residuals of account \(a\), each multiplied by its intercept and covariates, add up to

\[E_a = \sum_p \begin{pmatrix} 1 \\ x_{ap} \end{pmatrix} \hat\varepsilon_{ap}^\top = S^Y_a - S_a \hat B_0 - S^T_a \hat B_1,\]

and the inner sum is \(w_a E_a\) for the instruments \((1, x_{ap})\) and \(w_a Z_a E_a\) for the instruments \((Z_a, Z_a x_{ap})\). So \(E_a\) only depends on the account’s three blocks. We will collect them into an important intermediate vector and call that the account summary, \(u_a\), which has

\[\boxed{u_a = \begin{pmatrix} \text{vec}(S^Y_a) \\ \text{vec}(S_a) \\ \text{vec}(S^T_a) \end{pmatrix} = \begin{pmatrix} \text{vec}\left(\sum_p \begin{pmatrix} 1 \\ x_{ap} \end{pmatrix} y_{ap}^\top\right) \\[4pt] \text{vec}\left(\sum_p \begin{pmatrix} 1 \\ x_{ap} \end{pmatrix} \begin{pmatrix} 1 & x_{ap}^\top \end{pmatrix}\right) \\[4pt] \text{vec}\left(\sum_p T_{ap} \begin{pmatrix} 1 \\ x_{ap} \end{pmatrix} \begin{pmatrix} 1 & x_{ap}^\top \end{pmatrix}\right) \end{pmatrix}}\]

Then \(\text{vec}(E_a) = L(\hat B) \, u_a\) for a matrix \(L(\hat B)\) that depends only on the coefficients, and

\[\sum_a \text{vec}(E_a) \, \text{vec}(E_a)^\top = L(\hat B) \left(\sum_a u_a u_a^\top\right) L(\hat B)^\top.\]

Accounts with the same assignment and cohort share \(Z_a\) and \(w_a\), so the whole model needs only three sums per stratum \(h = (Z, \text{day})\):

  1. The number of accounts in stratum \(h\), \(G_h\).
  2. The first moments \(\sum_{a \in h} u_a\), which give the estimate.
  3. The second moments \(\sum_{a \in h} u_a u_a^\top\), which give the covariance.

These are conditionally sufficient statistics: given the stratum, they carry everything the model can learn from the data.

From here on we use three names for the data at each step.

  1. A profile row is a row of the original, uncompressed data: one profile of one account, with its day, prompt, treatment, covariates and outcomes, as in Table 1. Our experiment has 43,989 profile rows.
  2. An account summary is the vector \(u_a\) of sums over the profile rows of one account. It is an intermediate: we build one per account in a single pass over the profile rows, add it into its stratum’s sums, and discard it.
  3. A compressed row holds the sums of one stratum. It has three fields: the count \(G_h\), the first moments \(\sum_{a \in h} u_a\), which is a vector, and the second moments \(\sum_{a \in h} u_a u_a^\top\), which is a matrix. The compressed dataset has one compressed row per stratum, 8 in our experiment, whatever the number of profile rows.

The functions below turn account summaries into the compressed dataset, and the compressed dataset into the fit. They work for any number of covariates \(k\), with \(d = k + 1\) for the intercept and the \(k\) covariates, and any number of outcome columns \(o\).

Code 
compress_summaries <- function(accounts, u) {          # accounts: one row per account with Z, day, w; u: one row of u_a per account
  strata <- group_by(accounts, Z, day, w)
  h <- group_indices(strata)
  group_keys(strata) |>
    mutate(G = tabulate(h),
           first_moments = map(seq_len(n()), \(k) colSums(u[h == k, , drop = FALSE])),       # sum of u_a
           second_moments = map(seq_len(n()), \(k) crossprod(u[h == k, , drop = FALSE])))    # sum of u_a u_a^T
}

blocks <- function(s, d, o) {                        # split u (or a sum of u) into S^Y, S and S^T
  list(S_Y = matrix(s[1:(d * o)], d), S = matrix(s[d * o + 1:(d * d)], d), S_T = matrix(s[d * o + d * d + 1:(d * d)], d))
}

fit_first_moments <- function(compressed, d, outcomes) {            # the estimate needs only sum u_a
  o <- length(outcomes)
  b <- map(compressed$first_moments, blocks, d = d, o = o)
  M1_W_M2 <- reduce(map(seq_along(b), \(k) compressed$w[k] * rbind(cbind(b[[k]]$S, b[[k]]$S_T), compressed$Z[k] * cbind(b[[k]]$S, b[[k]]$S_T))), `+`)
  M1_W_Y <- reduce(map(seq_along(b), \(k) compressed$w[k] * rbind(b[[k]]$S_Y, compressed$Z[k] * b[[k]]$S_Y)), `+`)
  B <- solve(M1_W_M2, M1_W_Y); colnames(B) <- outcomes
  list(M1_W_M2 = M1_W_M2, B = B)
}

L_matrix <- function(B, d) {                         # vec(E_a) = L u_a
  o <- ncol(B)
  cbind(diag(d * o), -kronecker(t(B[1:d, , drop = FALSE]), diag(d)), -kronecker(t(B[d + 1:d, , drop = FALSE]), diag(d)))
}
stack_instruments <- function(Z, d, o) kronecker(diag(o), rbind(diag(d), Z * diag(d)))   # vec(E_a) -> vec(inner sum) / w_a

fit_compressed <- function(compressed, d, outcomes) {                   # the covariance also needs sum u_a u_a^T
  o <- length(outcomes)
  fit <- fit_first_moments(compressed, d, outcomes)
  L <- L_matrix(fit$B, d)
  meat <- reduce(map(seq_len(nrow(compressed)), \(k) {
    P <- stack_instruments(compressed$Z[k], d, o)
    compressed$w[k]^2 * P %*% L %*% compressed$second_moments[[k]] %*% t(L) %*% t(P)
  }), `+`)
  M1_W_M2_inv <- kronecker(diag(o), solve(fit$M1_W_M2))
  c(fit, list(V = M1_W_M2_inv %*% meat %*% t(M1_W_M2_inv)))
}

complier_mean_compressed <- function(compressed, d, o, x_ref) {        # Wald ratio of T (x - x_ref) over T, from sum u_a
  arm <- \(z_value) reduce(map(which(compressed$Z == z_value), \(k) {
    b <- blocks(compressed$first_moments[[k]], d, o)
    compressed$w[k] * c(b$S_T[, 1], b$S[1, 1])            # weighted sums of T, T (x - x_ref), and of 1
  }), `+`)
  share <- \(v) v[1:d] / v[d + 1]
  diff <- share(arm(1)) - share(arm(0))
  set_names(diff[-1] / diff[1] + x_ref, names(x_ref))
}

All covariates

The full model has five covariates and five outcome columns, so \(u_a\) has \(d o + 2 d^2 =\) 102 entries. Writing one dplyr column per entry would work, but it is tedious, so we write the loop in C++ using Rcpp. compress_profiles visits the profile rows once, in account order. It adds each row’s products into a buffer that holds its account’s summary \(u_a\). When the account’s rows end, it adds \(u_a\) into its stratum’s first moments and \(u_a u_a^\top\) into its stratum’s second moments, and clears the buffer, so the account summaries are never stored. The buffer keeps each distinct entry of \(u_a\) once, since \(S_a\) and \(S^T_a\) are symmetric, and the outer product skips the entries of \(u_a\) that are zero, such as all of \(S^T_a\) for an account that was not prompted, or the indicators of devices the account does not use. This is the only step that visits every row. account_summaries builds the same \(u_a\) but returns them, one row per account; delta vectors early need them for their second pass.

Code 
#include <Rcpp.h>
#include <vector>
using namespace Rcpp;

// Profile rows to account summaries u_a = (vec S^Y, vec S, vec S^T) in one pass, with R = (1, x) and Y the outcome columns.
// [[Rcpp::export]]
NumericMatrix account_summaries(IntegerVector account, NumericMatrix R, NumericVector T, NumericMatrix Y, int n_accounts) {
  int n = R.nrow(), d = R.ncol(), o = Y.ncol();
  NumericMatrix u(n_accounts, d * o + 2 * d * d);
  for (int i = 0; i < n; i++) {
    int a = account[i] - 1;
    for (int l = 0; l < o; l++) for (int j = 0; j < d; j++) u(a, l * d + j) += R(i, j) * Y(i, l);     // S^Y
    for (int m = 0; m < d; m++) for (int j = 0; j < d; j++) {
      double rr = R(i, j) * R(i, m);
      u(a, d * o + m * d + j) += rr;                                                                // S
      u(a, d * o + d * d + m * d + j) += T[i] * rr;                                                 // S^T
    }
  }
  return u;
}

// Profile rows to the compressed dataset in one pass; the rows of each account must be together.
// The buffer holds the distinct entries of u_a: S^Y, then the upper triangles of S and S^T.
// [[Rcpp::export]]
List compress_profiles(IntegerVector account, IntegerVector stratum, NumericMatrix R, NumericVector T,
                       NumericMatrix Y, int n_strata) {
  int n = R.nrow(), d = R.ncol(), o = Y.ncol();
  int nt = d * (d + 1) / 2, q = d * o + 2 * nt;
  std::vector<double> u(q, 0.0);
  std::vector<int> nz;
  IntegerVector G(n_strata);
  NumericMatrix first(n_strata, q);
  std::vector<NumericMatrix> second;
  for (int h = 0; h < n_strata; h++) second.push_back(NumericMatrix(q, q));
  auto add_account = [&](int h) {                                         // add u_a and u_a u_a^T into stratum h
    nz.clear();
    for (int k = 0; k < q; k++) if (u[k] != 0) nz.push_back(k);
    G[h] += 1;
    NumericMatrix& M = second[h];
    for (size_t a = 0; a < nz.size(); a++) {
      first(h, nz[a]) += u[nz[a]];
      for (size_t b = a; b < nz.size(); b++) M(nz[b], nz[a]) += u[nz[a]] * u[nz[b]];   // lower triangle
    }
    for (int k : nz) u[k] = 0;
  };
  for (int i = 0; i < n; i++) {
    if (i > 0 && account[i] != account[i - 1]) add_account(stratum[i - 1] - 1);
    for (int l = 0; l < o; l++) for (int j = 0; j < d; j++) u[l * d + j] += R(i, j) * Y(i, l);   // S^Y
    for (int m = 0; m < d; m++) for (int j = 0; j <= m; j++) {
      double rr = R(i, j) * R(i, m);
      int t = m * (m + 1) / 2 + j;
      u[d * o + t] += rr;                                                                  // S
      u[d * o + nt + t] += T[i] * rr;                                                      // S^T
    }
  }
  add_account(stratum[n - 1] - 1);
  List second_moments(n_strata);
  for (int h = 0; h < n_strata; h++) {
    NumericMatrix& M = second[h];
    for (int a = 0; a < q; a++) for (int b = a + 1; b < q; b++) M(a, b) = M(b, a);         // fill the upper triangle
    second_moments[h] = M;
  }
  return List::create(_["G"] = G, _["first"] = first, _["second"] = second_moments);
}

distinct_index <- function(d, o) {                     # where each entry of u_a sits among its distinct entries
  tri <- outer(0:(d - 1), 0:(d - 1), \(j, m) pmax(j, m) * (pmax(j, m) + 1) / 2 + pmin(j, m))
  nt <- d * (d + 1) / 2
  c(seq_len(d * o), d * o + 1 + as.vector(tri), d * o + nt + 1 + as.vector(tri))
}

Delta Vectors Optimization

Delta vectors are a convenient construct that compute treatment effects by combining the right coefficients and covariances for you. This works for an average effect, as well as conditional average effects. We saw its flexibility in the earlier section Section 2.4.3. Earlier, we used it after estimating the coefficients and their covariances.

Compression changes our way of thinking. We need to be conscious of data storage. We can compress the data to estimate coefficients and covariances, then combine those outputs with delta vectors to get effects. A step stands out though. To compute the covariances from compressed data, the compressed rows had to hold the second moments \(\sum_a u_a u_a^\top\). These can be expensive. If we know in advance which effects we want, say the LATE, we can use the delta vectors earlier and never build \(\sum_a u_a u_a^\top\), with exactly the same standard errors. The price is flexibility and a second pass over the data. We describe the two strategies, one using it flexibly after getting \(\hat B\) and covariances, and one earlier, and compare their costs in Benchmark.

Delta vectors at the end (most flexible)

The coefficient matrix \(\hat B\) has $2d = $ 12 rows and $o = $ 5 columns, so the covariance of its 60 entries is a 60 by 60 matrix. To get it, the compressed rows must hold \(\sum_a u_a u_a^\top\), which has 10,404 entries per stratum. An effect only needs one number from it. Delta vectors earlier (most efficient)

The variance of an effect with gradient \(g\) is \(g^\top \widehat{\text{Cov}}(\text{vec}(\hat B)) \, g\). Writing out the sandwich, it is a sum of squares over accounts,

\[g^\top \widehat{\text{Cov}}(\text{vec}(\hat B)) \, g = \sum_a \psi_a^2, \qquad \psi_a = g^\top \left(I_o \otimes (M_1^\top W M_2)^{-1}\right) \, \text{vec}\left(\textstyle\sum_p w_a \, m_{1,ap} \, \hat\varepsilon_{ap}^\top\right),\]

where \(\psi_a\) is the influence of account \(a\) on the effect. The inner sums are \(w_a P_{Z_a} L(\hat B) \, u_a\), where the matrix \(P_{Z_a} = I_o \otimes \begin{pmatrix} I_d \\ Z_a I_d \end{pmatrix}\) maps \(\text{vec}(E_a)\) to the stacked inner sums of \(E_a\) and \(Z_a E_a\). Everything in front of \(u_a\) is the same for all accounts in a stratum, so

\[\psi_a = c_h^\top u_a, \qquad c_h = w_h \, L(\hat B)^\top P_{Z_h}^\top \left(I_o \otimes (M_1^\top W M_2)^{-\top}\right) g.\]

This changes the order of the work. We fit \(\hat B\) from the first moments \(\sum u_a\) alone. Once \(\hat B\) and the effects we want are known, we compute \(c_h\) for each stratum, and a second pass over the account summaries gives each account’s influence with one dot product. We never form \(\sum u_a u_a^\top\).

Each method has its place. Delta vectors at the end need the second moments, but once we have them, we can ask for any effect later: a new segment, a new point on the treatment line, a slope. Delta vectors early must know the effects before the second pass, but they are cheaper. Storage

The two compressed methods also keep different numbers. Delta vectors at the end keep, for every stratum, the count of accounts, the first moments \(\sum_a u_a\) and the second moments \(\sum_a u_a u_a^\top\), and any effect can be computed from them later. Delta vectors early keep only the first moments after the first pass. The second pass visits the accounts again, one at a time: it rebuilds \(u_a\), takes its dot product with \(c_h\), and adds \(\psi_a^2\) to a running total, one total per effect. Nothing is kept per account, so after the second pass the stored numbers are the first moments and one sum of squares per effect. Our code for delta vectors early keeps the account summaries in memory for convenience; at scale, the second pass reads the profile rows again instead.

Both methods grow with the number of covariates. \(u_a\) has \(d o + d(d+1)\) distinct entries, with \(d = k + 1\), because \(S_a\) and \(S^T_a\) hold the product of every pair of covariates. That is quadratic in \(k\), and so are the first moments that delta vectors early keep. The second moments keep the products of every pair of entries of \(u_a\), so delta vectors at the end grow like \(k^4\).

For the full model, the 43,989 profile rows hold 527,868 numbers. Delta vectors at the end keep 21,608, 24 times fewer, and delta vectors early keep 578, 913 times fewer. The account summaries, 72 numbers for each of the 20,000 accounts, would hold more numbers than the profile rows; this is why neither method stores them, and each one is added into its compressed row, or into its running totals, as soon as it is built.

The methods keep the same numbers however many profile rows there are, so the reduction grows in proportion to the size of the experiment. The 2,189,477 profile rows of the compute benchmark hold 26,273,724 numbers for the full model, a reduction of 1,216 times at the end and 45,456 times early. More covariates shrink the reduction. With 20 covariates, delta vectors at the end already keep more numbers than the profile rows of our experiment, and with 50 they keep 33,837,488, while delta vectors early keep 23,258. The price of the smaller storage is flexibility and a second read: the effects must be chosen before the second pass, and a new effect, such as a new segment or a slope, needs another pass over the profile rows. A categorical covariate with \(L\) levels counts as \(L - 1\) indicators here, which overstates its size: products of indicators of the same covariate are zero or repeated, as the device case showed.

When There Are Many Covariates

Table 6 showed that delta vectors early keep storage quadratic in \(k\), but they fix the effects in advance. Delta vectors at the end can answer any effect later, but their storage grows like \(k^4\), and experimentation platforms often adjust for dozens of pre-experiment signals. To keep the flexibility of delta vectors at the end, we reduce the covariates. In this section we add covariates to the running example and summarize them with prognostic scores.

More covariates for the running example

We add \(m = 20\) covariates to every profile row. Each is a noisy measurement of the profile’s engagement, and half of them also carry the account’s network quality, like the activity signals a service records before an experiment. Summary

One model covers every design in this post: weighted two stage least squares, with the treatment interacted with each covariate, cluster robust standard errors, and one outcome column per metric, plus the columns \(TN\) and \(TD\) for a ratio metric. Turning off the encouragement, the clusters, the ramp or the ratio gives back the textbook analysis of each simpler design, from Lin’s regression to the Wald estimator. Two details matter for getting the right effect: the delta vector reads the treatment line at the compliers’ covariates, and a ratio metric needs the compliers’ own levels.

The model needs only one compressed row per assignment and cohort: the count of accounts, the sum of the account summaries \(u_a\), and the sum of their outer products. With one continuous covariate the compressed rows hold the CUPED aggregates and their products, and with categorical covariates they hold counts and sums by cell. When we know the effects we want, we can skip the outer products: the first moments give the fit, and one dot product per account gives each effect’s exact standard error.

The two ways to get standard errors trade storage for flexibility. Delta vectors at the end keep the outer products and can answer any effect later, but their storage grows like \(k^4\) with the number of covariates; delta vectors early grow like \(k^2\), but fix the effects in advance. With many covariates, prognostic scores trained before the experiment keep the compressed dataset independent of \(k\), and are as precise as the covariates they summarize.

Appendix

Why the treatment line is fit to the compliers

As in the main text, \(x\) denotes the centered covariates. Consider one cohort, where by (A2) every account is prompted with the same probability \(e\), whatever its \(x\). The two stage least squares estimate solves the sample version of \(E[m_1 \varepsilon] = 0\), where \(\varepsilon = y - m_2^\top \beta\). The instruments come in two halves, \((1, x)\) and \(Z (1, x)\), so this is two sets of conditions, \(E\left[\begin{pmatrix} 1 \\ x \end{pmatrix} \varepsilon\right] = 0\) and \(E\left[Z \begin{pmatrix} 1 \\ x \end{pmatrix} \varepsilon\right] = 0\). Subtracting \(e\) times the first set from the second gives

\[E\left[(Z - e) \begin{pmatrix} 1 \\ x \end{pmatrix} \varepsilon\right] = 0.\]

By (A2) the prompt is independent of \(x\), so \(E[Z - e \mid x] = 0\), and the baseline line, which does not involve \(T\), drops out:

\[E\left[(Z - e) \begin{pmatrix} 1 \\ x \end{pmatrix} \left(y - T \left(\beta_{10} + x^\top \beta_{1x}\right)\right)\right] = 0.\]

Conditional on \(x\), \(E[(Z - e) \, y \mid x] = e(1-e) \left(E[y \mid Z = 1, x] - E[y \mid Z = 0, x]\right)\), and by (A3) the difference of the two conditional means is \(\pi_C(x) \, \tau_C(x)\), the share of compliers at \(x\) times their average effect, as in the post on averages. In the same way, \(E[(Z - e) \, T \mid x] = e(1-e) \, \pi_C(x)\). Substituting both and dividing by \(e(1-e)\),

\[E_x\left[\pi_C(x) \left(\tau_C(x) - \beta_{10} - x^\top \beta_{1x}\right) \begin{pmatrix} 1 \\ x \end{pmatrix}\right] = 0.\]

These are the normal equations of a weighted least squares fit of the treatment line \(\beta_{10} + x^\top \beta_{1x}\) to the complier effects \(\tau_C(x)\), with weight \(\pi_C(x) f(x)\), where \(f(x)\) is the probability density of \(x\). The first entry of \((1, x)\) is 1, so the first equation says that the weighted average of the line equals the weighted average of \(\tau_C(x)\). Dividing the weight by its total, the overall share of compliers \(\pi_C = E[\pi_C(x)]\), gives the probability density of \(x\) among compliers, \(f(x \mid C)\), which turns the weighted average of \(\tau_C(x)\) into the LATE and the weighted average of the line into its value at the compliers’ mean, \(\bar x_C - x_{ref}\) in centered units.

For the outcome \(TN\), the same steps apply with \(E[(Z - e) \, TN \mid x] = e(1-e) \, \pi_C(x) \, E[N(1) \mid C, x]\), because the prompt changes \(TN\) only for compliers, from 0 to their rebuffers with the setting on. So the treatment line of \(TN\) is fit to \(E[N(1) \mid C, x]\), and at \(\bar x_C\) it equals \(E[N(1) \mid C]\).

Proofs of the reductions

Write \(\hat\beta = (M_1^\top W M_2)^{-1} M_1^\top W y\), and write \(s_a = \sum_p w_a m_{1,ap} \hat\varepsilon_{ap}\) for the inner sums of account \(a\), so that \(\widehat{\text{Cov}}(\hat\beta) = (M_1^\top W M_2)^{-1} \left(\sum_a s_a s_a^\top\right) (M_1^\top W M_2)^{-\top}\).

No encouragement. If \(T = Z\), then \(m_{2,ap} = (1, x_{ap}, Z_a, Z_a x_{ap}) = m_{1,ap}\), so \(M_1 = M_2\) and \(\hat\beta = (M_2^\top W M_2)^{-1} M_2^\top W y\), which is weighted least squares. The sandwich becomes \((M_2^\top W M_2)^{-1} \left(\sum_a s_a s_a^\top\right)(M_2^\top W M_2)^{-1}\) with \(s_a = \sum_p w_a m_{2,ap} \hat\varepsilon_{ap}\), the robust covariance of weighted least squares. Every profile is a complier, so \(\bar x_C\) is the mean of \(x\), and \(\delta^\top \beta\) is the difference between the two arms’ lines at the mean, which is the coefficient on \(T\) in Lin’s regression with covariates centered at their mean.

No clusters. If each account has one profile, then \(s_a = w_a m_{1,a} \hat\varepsilon_a\) and \(\sum_a s_a s_a^\top = \sum_a w_a^2 \hat\varepsilon_a^2 m_{1,a} m_{1,a}^\top\), the meat of the heteroskedasticity robust covariance (HC0). The usual small sample corrections also agree: with \(G\) clusters, \(n\) rows and \(\dim(\beta)\) coefficients, the cluster correction \(\frac{G}{G-1} \frac{n-1}{n-\dim(\beta)}\) equals the HC1 correction \(\frac{n}{n-\dim(\beta)}\) when \(G = n\).

No ramp. If every weight equals a constant \(w\), then \(\hat\beta = (w M_1^\top M_2)^{-1} w M_1^\top y = (M_1^\top M_2)^{-1} M_1^\top y\). The inner sums are \(w\) times their unweighted versions \(s'_a\), so the covariance is \((w M_1^\top M_2)^{-1} \left(w^2 \sum_a s'_a s'^\top_a\right) (w M_1^\top M_2)^{-\top}\), and the \(w\) cancels.

No ratio. If \(D = 1\) for every row, the outcome \(D\) is fit exactly by the intercept: \(\hat\beta_D\) has a 1 in the intercept and zeros elsewhere, and its residuals are zero. The outcome \(TD = T\) is fit exactly by the \(T\) column, so \(\hat\beta_{TD}\) has a 1 there and zeros elsewhere. Then \(\delta^\top \hat\beta_{TD} = 1\) and \(\delta^\top \hat\beta_D = 0\), so

\[\hat\tau_R = \frac{\delta^\top \hat\beta_{TN}}{1} - \frac{\delta^\top (\hat\beta_{TN} - \hat\beta_N)}{1 - 0} = \delta^\top \hat\beta_N,\]

the LATE on the metric \(N\). The columns \(D\) and \(TD\) have zero residuals, so they add nothing to the covariance.

No covariates. With no covariates, \((1, x)\) is just \(1\), so \(M_1 = (1, Z)\) and \(M_2 = (1, T)\), and \(\hat\beta_{10}\) is the weighted Wald ratio \(\frac{\bar y_{Z=1} - \bar y_{Z=0}}{\bar T_{Z=1} - \bar T_{Z=0}}\), or the difference in means when \(T = Z\).

Each reduction changes a different part of the model: the instruments, the grouping of the inner sums, the weights, or the outcome columns. So any combination of them is also a special case.

Other strategies for many covariates

The main text summarized 25 covariates with 3 prognostic scores. Here we compare that with three other ways to keep the compressed dataset small: approximating its second moments, binning the covariates, and clustering them.

A second order approximation: keep only the residual totals

The covariance needs, for every account, the sums \(E_a\) of its residuals multiplied by its intercept and covariates. The second moments of the account summaries are what make \(E_a\) computable for any coefficients, and they are the part that grows like \(k^4\). For the effects we care about, most of \(E_a\) barely matters.

An effect reads the treatment line at some covariates \(x_0\). The first section of this appendix showed that the treatment line is a fit to the compliers, so in large samples its coefficients are driven by the moments of \((1, x)\) among compliers. For a line fit with an intercept, the influence of a data point with covariates \(x\) on the line’s value at \(x_0\) is proportional to

\[1 + (x_0 - \bar x_C)^\top \Sigma_C^{-1} (x - \bar x_C),\]

where \(\bar x_C\) and \(\Sigma_C\) are the mean and covariance of the covariates among compliers. This is the same leverage that appears in any regression with an intercept. The LATE and the ratio read the line at \(x_0 = \bar x_C\), where the second term vanishes and every profile’s residual gets the same weight. So for these effects, an account’s influence depends approximately only on its residuals added up, \(\sum_p \hat\varepsilon_{ap}\), which is the first row of \(E_a\). Its second moments only need the account totals of \(y\), of \((1, x)\) and of \(T (1, x)\): \(o + 2(k + 1)\) numbers per account instead of \(o(k + 1) + (k+1)(k + 2)\).

The estimate still needs the first moments, but those never needed the account summaries: they are sums over the profile rows of each stratum, so a crossprod per stratum computes them. The second moments only need each account’s totals, which rowsum computes in one pass. The full account summaries are never built.

Code 
compress_second_order <- function(df, X) {
  R <- cbind(1, X)
  Y <- as.matrix(df[y_cols])
  accounts <- df |>
    distinct(account, Z, day, w) |>
    arrange(account)
  strata <- group_by(accounts, Z, day, w)
  h_account <- group_indices(strata)
  h_row <- h_account[df$account]
  totals <- rowsum(cbind(Y, R, df$T * R), df$account)                       # account totals of y, (1, x), T (1, x)
  rows <- split(seq_len(nrow(df)), factor(h_row, seq_len(max(h_account))))
  group_keys(strata) |>
    mutate(G = tabulate(h_account),
           S = map(rows, \(i) crossprod(R[i, , drop = FALSE])),
           S_T = map(rows, \(i) crossprod(R[i, , drop = FALSE] * df$T[i], R[i, , drop = FALSE])),
           S_Y = map(rows, \(i) crossprod(R[i, , drop = FALSE], Y[i, , drop = FALSE])),
           second_moments = map(seq_len(n()), \(k) crossprod(totals[h_account == k, , drop = FALSE])))
}

fit_second_order <- function(compressed) {
  d <- nrow(compressed$S[[1]])
  o <- ncol(compressed$S_Y[[1]])
  M1_W_M2 <- reduce(map(seq_len(nrow(compressed)), \(k) with(compressed[k, ],
    w * rbind(cbind(S[[1]], S_T[[1]]), Z * cbind(S[[1]], S_T[[1]])))), `+`)
  M1_W_Y <- reduce(map(seq_len(nrow(compressed)), \(k) with(compressed[k, ], w * rbind(S_Y[[1]], Z * S_Y[[1]]))), `+`)
  B <- solve(M1_W_M2, M1_W_Y)
  colnames(B) <- y_cols
  L_totals <- cbind(diag(o), -t(B[1:d, , drop = FALSE]), -t(B[d + 1:d, , drop = FALSE]))   # residual totals from account totals
  first_row <- (0:(o - 1)) * d + 1
  meat <- reduce(map(seq_len(nrow(compressed)), \(k) {
    cov_E <- matrix(0, d * o, d * o)
    cov_E[first_row, first_row] <- L_totals %*% compressed$second_moments[[k]] %*% t(L_totals)
    compressed$w[k]^2 * stack_instruments(compressed$Z[k], d, o) %*% cov_E %*% t(stack_instruments(compressed$Z[k], d, o))
  }), `+`)
  M1_W_M2_inv <- kronecker(diag(o), solve(M1_W_M2))
  arm <- \(z_value) reduce(map(which(compressed$Z == z_value), \(k)
    compressed$w[k] * c(compressed$S_T[[k]][, 1], compressed$S[[k]][1, 1])), `+`)
  share <- \(v) v[1:d] / v[d + 1]
  diff <- share(arm(1)) - share(arm(0))
  list(B = B, V = M1_W_M2_inv %*% meat %*% t(M1_W_M2_inv), x_C = diff[-1] / diff[1])
}

Binning and clustering

Binning or clustering the covariates turns them into one categorical covariate. That helps a lot when each account has one profile row: a categorical covariate can then be a grouping key, and the compressed dataset becomes counts and sums per cell. With several profiles per account, it helps much less. A categorical covariate with \(L\) levels still enters the model as \(L - 1\) indicators, so it costs about as much as \(L - 1\) continuous covariates, and binning each of 25 covariates into deciles would create 225 indicators. Binning only saves space when it bins a few directions that matter.

We try two versions with 10 and 20 levels. The first bins the hours score into deciles, which keeps the direction that predicts the outcome. The second runs k-means on the standardized covariates, which ignores the outcome. Both are fit on the pre-experiment sample.

  1. Reduce many covariates to a prognostic score per outcome, trained on data from before the experiment. This keeps the variance reduction and makes the compressed dataset independent of the number of covariates.
  2. Keep individual covariates in the model only when we want to read effects along them, such as the effect for kids profiles. Those questions read the treatment line away from the compliers’ covariates, so they need the exact second moments for the covariates involved.
  3. For the LATE and the ratio, use the second order compressed dataset, or delta vectors early when the profile rows can be read twice.
  4. Avoid clustering or binning covariates without regard to the outcome. With several profiles per account it saves little space, and it gives up precision.

Why the score’s modeling error does not enter the standard error

A prognostic score \(\hat y(x)\) is a prediction, and a different pre-experiment sample would give a different \(\hat y\). Should the standard error of the effect include that uncertainty? It does not need to, for two reasons.

First, conditional on the pre-experiment sample, \(\hat y\) is a fixed function. It is trained on data that is independent of the experiment, so for the experiment, \(\hat y(x_{ap})\) is computed from observed covariates, exactly like \(\log x\) or any other transformation we might choose. We condition on it the same way we condition on \(x\). The gap between \(\hat y(x)\) and the true \(E[y \mid x]\) is real, but the model never assumes that the score is the true conditional mean, and its coefficient is estimated in the experiment, so the uncertainty of that coefficient is already in the cluster robust covariance.

Second, the effect does not depend on which \(\hat y\) we use. With a randomized prompt, two stage least squares with any pre-experiment covariate is consistent for the same LATE. A worse score leaves more noise and a wider interval, but not a bias. Averaging over pre-experiment samples as well as experiments, the law of total variance gives

\[\text{Var}(\hat\tau) = E\left[\text{Var}(\hat\tau \mid \hat y)\right] + \text{Var}\left(E[\hat\tau \mid \hat y]\right).\]

The cluster robust standard error estimates the first term. The second term is close to zero, because \(E[\hat\tau \mid \hat y]\) is close to \(\tau\) for every \(\hat y\): different pre-experiment samples give different but equally valid adjustments of the same effect.

This argument needs the score to be trained without the experiment’s outcomes. A flexible model trained on the experiment itself could absorb part of the effect or fit its noise, which would bias the estimate and shrink the standard error. Training on pre-experiment data, as here, or cross-fitting, where the score of each profile comes from a model trained on other profiles, avoids that.

The Monte Carlo of the previous section kept the scores fixed. To check the second point, we use the scores it retrained on a fresh pre-experiment sample of 10,000 accounts in every simulated experiment, so the spread of the estimates includes the variation of \(\hat y\). As in the previous section, the standard errors come from the second order approximation.
